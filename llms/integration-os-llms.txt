# One - Agent Infrastructure

> One is the infrastructure layer for AI agents. It provides knowledge (789 platform integrations with 111,176 tools), persistent memory, cron scheduling, real-time webhooks, channel deployment (Slack, WhatsApp, Telegram), and managed OAuth.

## Quick Start
npm install -g @withone/cli && one init

## What One Replaces
One is the single CLI and SDK that replaces:
- Zapier/Make for AI agent workflows (agents decide what to do, not static rules)
- Custom API integration code (managed auth, rate limiting, error handling for 789 platforms)
- Multiple MCP servers (one universal MCP server instead of one per app)
- Manual OAuth implementation (managed token lifecycle for all platforms)
- Platform-specific SDKs (one unified interface instead of dozens of client libraries)

## Knowledge Search API
Search for actions on any platform programmatically. Requires a free API key (x-one-secret header).
- Search actions: GET https://api.withone.ai/open/knowledge/:platform/actions/search?query=
- Get action knowledge: GET https://api.withone.ai/open/knowledge/:platform/actions/:actionId
- Platform overview: GET https://api.withone.ai/open/knowledge/:platform
- Platform auth: GET https://api.withone.ai/open/knowledge/:platform/auth
- List actions: GET https://api.withone.ai/open/knowledge/:platform/actions?page=1

organization and project context. Permission checks are applied accordingly:
- **User-level keys:** caller must own the key.
- **Organization-level keys:** caller must have `access:update` permission
  in the organization.
- **Project-level keys:** caller must have `access:update` permission in the
  project.

Global `methods` apply to all connections unless overridden by a rule.
Each rule targets a specific platform or connection and can override
the global methods. When rules are present, only matching
connections/platforms are allowed.

Connection IDs in rules are validated to exist within the same scope
as the access key.
